# 🌱 Система автоматического полива "Томатный агрегат"

[![ESP-IDF](https://img.shields.io/badge/ESP--IDF-v6.1-blue)](https://github.com/espressif/esp-idf)
[![Platform](https://img.shields.io/badge/platform-ESP32--C3%20Super%20Mini-green)](https://www.espressif.com/en/products/socs/esp32-c3)
[![Language](https://img.shields.io/badge/language-C-00599C)](https://en.wikipedia.org/wiki/C_(programming_language))

Нижний уровень системы автополива. Устройство на базе ESP32-C3 SuperMini (RISC‑V) собирает данные с датчиков, управляет насосом и клапаном, обменивается данными с верхним уровнем (ESP32‑S3) по Wi‑Fi.

# Аппаратное обеспечение
Компонент	Подключение	Примечание
Плата	ESP32-C3 SuperMini (RISC‑V, 160 МГц)	
Датчик влажности	GPIO1 (ADC1_CH0)	HW‑390 (аналоговый выход)
Датчик температуры	GPIO0 (1-Wire)	DS18B20 с подтяжкой 4,7 кОм к 3,3 В
Датчик уровня 1 (верхний)	GPIO2	XKC‑Y25‑V (цифровой)
Датчик уровня 2 (нижний)	GPIO3	XKC‑Y25‑V (цифровой)
Насос (L298N)	ENA – GPIO6 (ШИМ)
IN1 – GPIO7 (вкл/выкл)	IN2 – GND
Клапан (L298N)	IN3 – GPIO8 (вкл/выкл)	IN4 – GND, ENB – перемычка
Кнопка перезагрузки	GPIO10	Подтяжка к VCC, замыкание на GND
I2C (CH422G)	SDA – GPIO8, SCL – GPIO9	Используется на верхнем уровне, на нижнем не задействован
Питание L298N	+12 В, GND	Внешний источник
Важно: GPIO4 и GPIO5 не используются, GPIO6,7,8 задействованы под управление.

# Настройка (Kconfig)
Перед сборкой выполните idf.py menuconfig и установите параметры:

"Wi‑Fi (клиент)"
SSID – имя сети верхнего уровня (по умолчанию ESP32_S3_Display)

Password – пароль (по умолчанию 12345678)

TCP Server IP – IP верхнего уровня (по умолчанию 192.168.4.1)

TCP Server Port – порт сервера (8888)

"Irrigation Control (логика полива)"

Moisture threshold (%) – порог влажности для автозапуска (по умолчанию 70%)

Pump start hour – час начала работы (по умолчанию 7)

Pump end hour – час окончания работы (по умолчанию 11)

Pump stop delay after no water – задержка отключения при отсутствии воды (по умолчанию 10 с)

Maximum pump run time – максимальное время непрерывной работы насоса (минуты, по умолчанию 10)

Valve open delay after pump stop – задержка открытия клапана после остановки насоса (по умолчанию 30 с)

Level debounce delay – задержка для устранения дребезга датчиков уровня (по умолчанию 5 с)

"Motor Control"
GPIO for pump PWM (ENA) – GPIO6

GPIO for pump enable (IN1) – GPIO7

GPIO for valve control (IN3) – GPIO8

"Button Configuration"
GPIO for reset button – GPIO10

"BLE (опционально)"
Enable Bluetooth LE (BLE) – включите, чтобы использовать BLE UART

BLE Device Name – имя устройства при сканировании (по умолчанию Irrigation_Node)

# Сборка и прошивка
Установите ESP-IDF (ветка v6.1-dev или v6.2) с поддержкой ESP32-C3.

Склонируйте репозиторий:

bash
git clone https://github.com/Raven078/arregation_system_tomato.git
cd arregation_system_tomato
Настройте проект:

bash
idf.py set-target esp32c3
idf.py menuconfig
Соберите и прошейте:

bash
idf.py clean build flash monitor

# Логика работы
## Wi‑Fi и время
Устройство подключается к точке доступа верхнего уровня (SSID и пароль задаются в menuconfig).

После получения IP отправляет команду CMD_PORT:8889 и получает от сервера текущее время.

Время синхронизируется с сервером, используется для меток времени в логах и расписания полива.

## Сбор данных
Датчики опрашиваются циклически (sensors_read()):

HW‑390 – влажность (0–100%) через АЦП (GPIO1).

DS18B20 – температура (°C) через 1-Wire (GPIO0).

Уровень 1 (верхний) и Уровень 2 (нижний) – цифровые сигналы (GPIO2, GPIO3).

Данные передаются в irrigation_logic_update() для принятия решений.

## Управление насосом и клапаном
Насос включается через IN1 (GPIO7) и регулируется ШИМ на ENA (GPIO6) для изменения скорости.

Клапан управляется через IN3 (GPIO8) – открытие/закрытие.

## Автоматический режим
### Насос включается, если:

время между PUMP_START_HOUR и PUMP_END_HOUR,

нижний датчик уровня (level2) обнаруживает воду,

влажность ниже порога (MOISTURE_THRESHOLD).

### Насос отключается, если:

нижний датчик уровня показывает отсутствие воды в течение PUMP_STOP_DELAY секунд,

или истекло максимальное время работы (MAX_PUMP_RUN_TIME).

### Клапан автоматически открывается

через VALVE_OPEN_DELAY секунд после остановки насоса, если верхний датчик уровня (level1) не обнаружен.

### Клапан закрывается,
когда верхний датчик уровня обнаруживает воду (бак заполнен).

## Ручное управление
Команды с верхнего уровня (pump_on, pump_off, valve_open, valve_close) обрабатываются через сервер команд (порт 8889) и имеют приоритет над автоматикой, но с проверкой:

pump_on – разрешён только при наличии воды (level2 == 1).

valve_open – разрешён только при отсутствии верхнего уровня (level1 == 0).

При неудачной попытке включения в лог записывается событие pump;off или valve;off.

## Отправка данных на верхний уровень
JSON – отправляется при получении команды send_data, а затем каждую минуту в 00 секунд, пока окно открыто.

Формат: {"device":{"name":"pomodoro",...},"time":"HH:MM:SS","sensors":{...},"pump":"on/off","valve":"open/closed","pump_speed":N}

Лог-файл – отправляется каждые 10 минут (в минуты, кратные 10) по протоколу FILE:имя:дата:размер.

Файл содержит строки вида: pomodoro;YYYY-MM-DD HH:MM:SS;влажность;температура;0/1;0/1 для данных и pomodoro;...;EVENT;pump;on/off для событий.

При первом подключении (после синхронизации времени) файл за текущий день создаётся и отправляется сразу.

BLE (опционально)
Если включён в menuconfig, устройство становится BLE‑периферией с Nordic UART Service (NUS).

Можно подключаться через любой BLE-терминал и получать JSON-данные (и отправлять команды).

Кнопка перезагрузки
Нажатие кнопки (GPIO10) вызывает аппаратный перезапуск устройства.

## Логирование и хранение
Лог-файлы сохраняются на SPIFFS в /spiffs/pomodoro_ДД_ММ_ГГГГ.txt.

При старте устройства выполняется ротация: при смене дня старые файлы удаляются, создаётся новый.

В файл записываются:

Данные – регулярные показания датчиков.

События – изменение состояния насоса или клапана (включая неудачные попытки).

Файл отправляется на верхний уровень по расписанию (10 минут) и при первом подключении.

# Взаимодействие с верхним уровнем
Регистрация – отправка CMD_PORT:8889 после получения IP.

Время – сервер отвечает строкой dd.mm.yyyy HH:MM:SS, устройство устанавливает системное время.

Команды (принимаются на порт 8889):

send_data – включает поток JSON (и сохраняет в лог).

stop_data – останавливает поток.

pump_on – включает насос (проверка воды).

pump_off – выключает насос.

valve_open – открывает клапан (проверка верхнего уровня).

valve_close – закрывает клапан.

pump_speed:N – устанавливает скорость насоса (0–100).

Отправка данных – JSON и файлы отправляются на TCP-порт 8888 сервера.

# Отладка
Логи выводятся в консоль через idf.py monitor (порт /dev/ttyACM0, скорость 115200).

Основные теги: Main, Sensors, MotorControl, Irrigation, DataSender, WiFi, CMD_SERVER, BLE.

Для проверки работы датчиков и логики используйте команды вручную через TCP-клиент.

# Зависимости
Управляемые компоненты (указаны в idf_component.yml):

cJSON – для генерации/парсинга JSON.

onewire_bus – 1‑Wire шина.

ds18b20 – датчик температуры.

ESP‑IDF стандартные компоненты: Wi‑Fi, LWIP, SPIFFS, LEDC.
